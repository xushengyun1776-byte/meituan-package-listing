# 美团外卖商家后台 CDP 自动化 —— 踩坑记录（完整复盘）

> 项目：`meituan-套餐上架-2026-10-29`
> 场景：用 Edge 远程调试端口（CDP）+ Python 脚本，自动化美团外卖商家后台
> 「商品管理 → 新建套餐 → 分组可选套餐」的完整上架流程。
>
> 本文记录**每一个真实踩过的坑**，按「症状 → 根因 → 解法」组织。
> 全部坑都是在「看起来像选择器写错了 / 元素不存在」的表象下，
> 实际是**渲染时序、事件模型、动画时钟**三个层面的问题。

## 零、先看这张图：三个层次的心智模型

```
┌─ 第 3 层：CDP 协议层 ────────────────────────────────┐
│  · Runtime.evaluate 的异常被静默吞掉                  │
│  · returnByValue 不能返回 DOM 元素                    │
│  · CDP 事件只在 send() 等待响应期间被读取             │
└───────────────────────────────────────────────────────┘
┌─ 第 2 层：浏览器渲染/事件模型 ─────────────────────────┐
│  · 后台标签页冻结 CSS 动画时钟                          │
│  · roo 组件离场动画残留节点不删除                      │
│  · React 受控组件 / 事件委托 / pointer-events          │
└───────────────────────────────────────────────────────┘
┌─ 第 1 层：美团业务逻辑 ───────────────────────────────┐
│  · 多层 iframe（顶层 → editPack → selectProduct）     │
│  · 弹窗内搜索框不触发检索（得走分组树）                │
│  · 「已设置的值」在 DOM 显示上滞后（得读 fiber）        │
└───────────────────────────────────────────────────────┘
```

**排查口诀**：DOM 读不到 → 先怀疑第 3 层；读到了但点不动 → 怀疑第 2 层；
读到了也点了但业务没变 → 怀疑第 1 层。

## 一、动画时钟类（2026-10-29 最后一个、也是最隐蔽的坑）

### 坑 1 ★★★ 浏览器在后台 → CSS 动画被冻结 → 弹窗停在入场第 0 帧

**症状**
- 弹窗 DOM 明明插进来了，文本也读得到，但**什么都点不动**。
- 「上传图片」裁剪弹窗里，「保存图片」按钮 `pointer-events: none`，
  `getBoundingClientRect()` 全是 `0x0`。
- 看起来像「按钮被 disabled 了」「裁剪画布没初始化」。

**根因**

Edge 标签页在后台时 `document.visibilityState === "hidden"`。
Chrome **不推进 hidden 页面的 CSS 动画时钟** —— 实测：

```js
document.getAnimations().map(a => a.animationName + ' ' + a.playState + ' ' + a.currentTime)
// → ['rooDialogFadeIn running 0', 'rooDialogZoomIn running 0']
//                        ^^^^^^^^^^^ currentTime 永远是 0
```

于是弹窗永远停在入场动画的 **0% 关键帧**：

| 元素 | 0% 关键帧的状态 | 后果 |
|---|---|---|
| `div.roo-modal`（遮罩） | `opacity: 0` | 看不见，但**铺满全屏** |
| `.roo-modal-dialog` | `transform: matrix(0,0,0,0,0,0)` | **缩放为 0**，子元素 rect 全 0 |
| `button.roo-btn` | `pointer-events: none` | 点不动 |

判别特征（一眼认出）：

```
div.roo-modal  class="roo-modal backdrop roo-mask-motion-appear roo-mask-motion-appear-active roo-mask-motion"
               opacity=0  animationName=rooDialogFadeIn  animationPlayState=running
dialog        offsetWidth=840  offsetHeight=624   ← 布局尺寸正常！
              getBoundingClientRect() = 0x0        ← 但视觉尺寸是 0
```

**注意 `offsetWidth` 与 `getBoundingClientRect().width` 的差异**：
transform 缩放**不影响布局尺寸**，只影响视觉 rect。
所以判断「弹窗到底开没开」必须用 `offsetWidth`，不能用 `getBoundingClientRect().width`。

**解法（两道保险）**

```python
def wake(self):
    """叫醒页面。Emulation.setFocusEmulationEnabled 比 Page.bringToFront 更温和：
    它让页面「认为有焦点」，即使标签页在后台也照常推进动画，
    不会把用户的浏览器窗口抢到前台。"""
    try: self.send("Emulation.setFocusEmulationEnabled", enabled=True)
    except Exception: pass
    try: self.send("Page.bringToFront")
    except Exception: pass

def finish_animations(self, ctx_id):
    """把所有 CSS 动画/过渡直接推到终态（兜底）。"""
    return self.evaluate(
        "(()=>{ if(!document.getAnimations) return 'NA';"
        " let n=0; for(const a of document.getAnimations()){ try{ a.finish(); n++; }catch(e){} }"
        " return 'finished='+n; })()", ctx_id)
```

效果（实测）：

```
wake + finish 之后：
  modal    op=1  cls=roo-modal backdrop
  dialog  rect=840x624 @743,302  transform=none  pe=auto
  BTN      pe=auto   elementFromPoint 命中 SPAN ✓
```

**已固化到 `form.cdp_connect()`**，所有脚本自动受益。

### 坑 2 ★★ 弹窗离场后遮罩节点不删除 → 吃掉所有 hover / 坐标点击

**症状**
- 弹窗明明关了，后续所有坐标点击都无效。
- 但 JS 合成事件一切正常 —— 极具迷惑性。

**根因**

美团用 `roo` 组件的离场动画关闭弹窗，动画结束后**节点不被移除**：

| 残留类型 | class | opacity | display | 是否拦截点击 |
|---|---|---|---|---|
| 弹窗遮罩 | `roo-mask-motion-leave` | **0** | block | **是**（铺满全屏） |
| 下拉浮层 | `roo-popup-motion-leave` | **1** | block | 是（**肉眼可见地盖住表单**） |

下拉浮层那个 opacity 还是 1，肉眼能看见它挂在「+ 添加商品」按钮上方。

**解法**：`form.purge_modals(cdp, cid)` 清理。见坑 3。

### 坑 3 ★★ purge_modals 的白名单：motion-leave 要**一律删**，正在打开的要**保留**

**症状**

清理脚本写了白名单 `KEEP=/店内商品|上传图片|套餐拼图推荐/`，
用来防止把「商品选择弹窗」「裁剪弹窗」本体误删。结果**删不掉该删的**：

```
残留遮罩 class = "roo-modal backdrop roo-mask-motion-leave ..."
innerText 含「上传图片」 → 命中 KEEP → 跳过 → 遮罩永远留着
```

后果：后续 `mouseMoved` 悬停缩略图时，`:hover` 链停在遮罩上：

```
HTML < BODY < DIV.app-root < DIV.roo-modal backdrop roo-mask-   ← 停在这
```

缩略图的删除按钮永远不显现，删除操作 100% 失败。

**解法：把「离场」和「正在打开」区分开**

```javascript
// 1) 离场动画残留 —— 一律移除（不再做 KEEP 豁免）
for(const e of document.querySelectorAll('[class*=motion-leave]')){
  try{ e.remove(); o.push('leave:'+String(e.className).slice(0,26)); }catch(e){}
}
// 2) 透明的 roo-modal（仍在「入场」但动画被冻结的）—— 保留白名单内的
for(const e of document.querySelectorAll('div.roo-modal')){
  const st=getComputedStyle(e);
  if(KEEP.test(e.innerText||'')) continue;
  if(parseFloat(st.opacity)<=0.05 && st.display!=='none'){
    try{ e.remove(); ... }catch(e){}
  }
}
```

判据是 **class 里有没有 `motion-leave`**，而不是内容文本：
`leave` = 正在离场（一定该删）；`appear` = 正在入场（要留）。

## 二、CDP 协议层

### 坑 4 ★★★ CDP 事件只在 `send()` 等待响应期间被读取 —— 清空 events 会永久丢事件

**症状**

商品选择弹窗明明打开了，`contexts()` 里却**找不到**它的 executionContext。
后续所有针对弹窗的操作全部落空。

**根因**

`clicktext.CDP.send()` 的实现是「发一条命令 → 阻塞读 websocket → 收到响应就返回；
期间收到的其他消息塞进 `self.events`」。

而 `contexts()` 里原本有一行 `self.events = []`（清空）。
新 iframe 的 `Runtime.executionContextCreated` 事件是在
**「清空之后、下一次 send() 之前」** 这个窗口里到达的 —— 事件进了 websocket 缓冲区，
但没人读，等下次 send() 开始读时…… 已经被下一次 events 列表覆盖或压根没被收集到，
**这个 contextId 就永久丢失了**。

**解法**

```python
def contexts(self):
    self.send("Runtime.enable")
    time.sleep(0.4)          # 原 1.0s，流水线整体超时
    for e in self.events:   # ★ 只读，不清空
        ...
    if len(self.events) > 600:
        self.events = self.events[-400:]   # ★ 裁剪，不清空
```

### 坑 5 ★★★ `Runtime.evaluate` 的 JS 异常被**静默吞掉** → 全部伪装成「元素不存在」

**症状**

某段 JS 取元素列表永远返回空。但同一段 JS 逻辑人工在 DevTools 里跑是对的。
排查时反复怀疑 CSS 类名、怀疑选择器，改了十几遍都没用。

**根因**

`Runtime.evaluate` 对 JS 的**语法错误**和**运行时错误**都不抛 Python 异常，
只把信息放进 `result.exceptionDetails`。原实现直接 `return res.get("value")` → **返回 None**。
调用方一律把 None 当成「元素不存在」。

真实的 bug 长这样（`.filter` 写错了作用对象）：

```javascript
// ❌ 错：.filter 作用在对象上 → TypeError
const a = {...}.filter(Boolean);
// ✅ 对：.filter 作用在 map 的结果数组上
const a = [...document.querySelectorAll('div[class*=tag-list-item]')]
    .map(e => { const c = e.querySelector('div[class*=content]'); return c ? c.innerText.trim() : ''; })
    .filter(Boolean);
```

**解法**

```python
class JSError(RuntimeError): pass

def evaluate(self, expr, ctx=None, strict=False):
    r = self.send("Runtime.evaluate", **params)
    if strict:
        det = r.get("result", {}).get("exceptionDetails")
        if det:
            desc = det.get("exception", {}).get("description") or det.get("text") or "JS error"
            raise JSError("%s\n  expr: %s" % (desc, expr[:300]))
    return r.get("result", {}).get("result", {}).get("value")
```

并把所有「取元素列表」的调用都改成 `strict=True`。
**收益**：错误信息直接告诉你哪一行错了，排查时间从几小时降到几分钟。

### 坑 6 ★★ `returnByValue=True` 时不能返回 DOM 元素

**症状**

```
Object reference chain is too long
```

**根因**：`returnByValue=True` 要求把结果**深拷贝**成 JSON。
DOM 节点的对象引用链无限长，序列化必然爆。

**解法**：JS 一律返回 **字符串 / 布尔 / 普通对象**：

```javascript
// ❌ return element;
// ✅ return JSON.stringify({x: r.x, y: r.y});
// ✅ return e ? 'YES' : 'NO';
```

### 坑 7 ★★ `DOM.setFileInputFiles` 之后 input 立刻消失

**症状**

`setFileInputFiles` 明明返回成功，紧接着 `document.querySelector('input[type=file]')` 却返回 null，
看起来像「文件没设上」。

**根因**：设上文件后，cropper 组件立刻读走文件并触发 React 重渲染，
input 节点被替换/移除。**这是正常现象**，反而说明组件已经消费到文件了。

**解法**：不要把「input 找不到」当成错误；用**裁剪画布里是否出现图**来判定成功。

## 三、React / DOM 事件模型

### 坑 8 ★★★ `<button>` 上直接派发合成事件**不触发** React onClick

**症状**

```javascript
button.dispatchEvent(new MouseEvent('click', {bubbles:true}));   // 无反应
```

**根因**：美团用的 `roo` 组件库把按钮渲染成：

```html
<button class="roo-btn roo-btn-primary" style="pointer-events:none">
  <span>保存图片</span>          <!-- 真正可点的 -->
</button>
```

`pointer-events:none` 是**有意为之**（配合 `::after` 伪元素扩大热区 / 避免嵌套交互），
真正绑定交互的是内部 `<span>`。

**解法**：点内部子元素。

```python
JS_CLICK = """(()=>{
  let e=(%s); if(!e) return 'no-el';
  try{ if(e.tagName==='BUTTON'||e.tagName==='A'){
         const inner=e.querySelector('span, i, em, svg'); if(inner) e=inner; } }catch(err){}
  ...
})()"""
```

**通用价值**：这条同时解释了「新建套餐」下拉菜单点不中、
「保存图片」点不动、「确定」按钮点不动等一整串现象。

### 坑 9 ★★ React 受控输入：原生 setter 会污染 value tracker

**症状**

```javascript
input.value = '新值';    // UI 没变，或 onChange 不触发
```

**根因**：React 给 input 挂了一个 value tracker（记录上一次的值）。
直接赋 `input.value` 会把 tracker 也一起改掉，
React 下次比较时认为「值没变」→ **不触发 onChange**。

**解法**（`form.type_into` 的做法）：

```python
cdp.evaluate("e.focus(); e.select();")     # 选中全部
cdp.send("Input.insertText", text=text)    # 走原生输入通道
# 回读校验
```

`Input.insertText` 会替换当前选区，因此不需要清 value，tracker 不会被污染。

### 坑 10 ★★ `Input.insertText` 会打进「当前焦点所在的那个输入框」

**症状**

组名变成了「加料二选一1」—— 本该填进「选 N」框的 "1" 跑到了组名框里。

**根因**：`Input.insertText` **不看目标元素**，只看**当前焦点**。
如果定位目标输入框的表达式失败了，代码却继续往下走 insertText，
"1" 就被打进了当时恰好获得焦心的另一个框。

**解法**：定位失败必须**立即中止**。

```python
exists = cdp.evaluate("(()=>{const e=(%s); return e?'YES':'NO';})()" % expr, cid)
if exists != "YES":
    return "no-element"      # ★ 绝不能继续 insertText
```

### 坑 11 ★ React fiber props 才是「真值」

**症状**

「组类型」下拉已经选了「固定商品」，但脚本读 `input.value` 仍是「可选商品」，
于是脚本认为没设置成功，又去点了一遍下拉 → **点到了同名错项**，类型反而被改错。

**根因**：受控 input 的 `value` 属性是 React 上一次渲染时写进去的，
存在**显示滞后**。真正的当前值在 React fiber 的 `memoizedProps` 里。

**解法**

```javascript
for(const el of document.querySelectorAll('div[class*=group-header], div[class*=group-wrap-item]')){
  const k = Object.keys(el).find(x => x.startsWith('__reactFiber'));
  let f = el[k], d = 0;
  while(f && d < 12){
    const p = f.memoizedProps || {};
    if(p && p.groupName !== undefined && p.groupType !== undefined){
      // groupType: 0 = 固定商品, 1 = 可选商品
      ftypes.push({name: p.groupName, gtype: p.groupType, skuCount: p.skuCount});
      break;
    }
    f = f.return; d++;
  }
}
```

**顺带**：设置下拉时先比对当前值，**已等于目标就跳过**，
否则 `select_popup` 会点到同名的那一项。

### 坑 12 ★★ hover 弹出的 tooltip 会**盖住**要点的按钮

**症状**

缩略图的删除按钮 `display:none`，hover 才显现。
按 hover 出来的坐标去点 → 点了 8 次，图片一张没少。

**根因**

`elementFromPoint` 实测命中的是：

```
DIV.roo-tooltip roo-tooltip-light roo-toolti     ← tooltip，不是 closeIcon
```

tooltip 正好浮在删除按钮上方。

**解法**：**不要用坐标点击，用合成事件**。合成事件不走 hit-test。

```javascript
const c = li[0].querySelector('img[class*=closeIcon]');
c.dispatchEvent(new MouseEvent('click', {bubbles:true, cancelable:true, view:window}));
```

对 `display:none` 的元素派发合成事件同样有效，React onClick 正常触发。

## 四、多层 iframe / 上下文

### 坑 13 ★★★ 美团后台是多层 iframe

```
顶层 frame  #/gw/static_resource/product#/listView      ctx 1619
 └─ 业务 iframe  .../product#/editPack                    ctx 1637   ← 表单
     └─ 弹窗 iframe  .../selectProduct                    ctx 16xx   ← 商品选择
```

`Runtime.evaluate` 必须带 `contextId`，且**每个 context 是独立的 JS 世界**。

### 坑 14 ★★★ 商品选择弹窗可能**同时存在多个** selectProduct iframe

React 重建 iframe 时旧的**不销毁**，页面上可能挂着 2~3 个 `selectProduct` iframe。

**解法**：不要拿第一个就返回，要挑**分组树渲染得最完整**的那个。

```python
for attempt in range(tries):
    best, best_n = None, -1
    for c in cdp.contexts():
        u = cdp.evaluate("location.href", c["id"]) or ""
        if "selectProduct" not in u and "selectGoods" not in u: continue
        n = _group_count(cdp, c["id"])          # 数分组树条目
        if n > best_n: best_n, best = n, c
    if best is not None and best_n > 0: return best
```

**判据要够严**：表单里的规格组也有 `span.custom-checkbox`，
只用「有没有 checkbox」会把**表单**误判成弹窗。

### 坑 15 ★★ iframe 被 React 重建 → contextId 失效

**症状**：`Cannot find context with specified id`

**解法**：所有弹窗操作走 `pick.Modal` 封装 —— 每次操作前 `refresh()` 重新定位 context。

### 坑 16 ★ 坐标口径：getBoundingClientRect 是视口坐标，getBoxModel 是文档坐标

`clicktext.page_coords_all` 因此输出 **4 种候选坐标**（加不加 iframe 偏移 × 两种取值），

## 五、业务逻辑层（美团特有）

### 坑 17 ★★★ 弹窗内的搜索框**完全不触发检索**

**症状**：在「上传图片」/「商品选择」弹窗里往搜索框打字、敲回车，
列表纹丝不动。`Input.insertText` 也打不进去（焦点根本没落在输入框上）。

**解法**：改走**左侧分组树导航** —— 点分组 → 在中间列表里找商品 → 点复选框。

```
┌──────────────┬───────────────────────┬──────────────┐
│ 分组树        │ 商品列表              │ 已选区        │
│ x < 205      │ 205 ~ 625             │ x >= 625     │
└──────────────┴───────────────────────┴──────────────┘
```

`pick.py` 因此重建为 `find_groups_for()` + `pick_auto()`：
先扫一遍分组树建立「商品名 → 分组名」映射，再逐个商品导航过去勾选。

const b = [...document.querySelectorAll('button')]

### 坑 19 ★★ 视口外的元素，合成事件点了没反应

**症状**：「组类型」下拉触发器的 `getBoundingClientRect().y = -496`（在视口上方），
派发合成事件完全没反应。

**根因**：视口外的元素不参与命中测试，很多组件的逻辑直接 return。

**解法**：先 `scrollIntoView({block:'center'})`，**等 0.7 秒**滚动结束，再派发事件。

```python
def js_click(self, ctx_id, expr, scroll=False):
    if not scroll:
        need = self.evaluate("...元素是否超出视口? 'YES':'NO'...", ctx_id)
        if need == "YES":
            self.evaluate("...scrollIntoView({block:'center',inline:'center'})...", ctx_id)
            time.sleep(0.7)
```

> 顺带：滚动等待从 0.35s 提到 0.75s —— 0.35s 时元素还在动，
> 读到的 rect 和点击时的位置对不上，点击落空。

### 坑 23 ★★ npm 生成的 `.cmd` shim 会卡死

`dsh.cmd` / `claude.cmd` 这类 shim 最后一行是 `... || title%COMSPEC% & "node" ...`。

## 七、通用排查手法备忘

| 目的 | 手法 |
|---|---|
| 看某元素是否真在页面上 | `document.elementFromPoint(x, y)`（能穿透 iframe 内的遮罩判断） |
| 看当前 hover 命中谁 | `[...document.querySelectorAll(':hover')].map(e => e.tagName+'.'+e.className)` |
| 看 CSS 动画卡在哪 | `document.getAnimations().map(a => a.animationName+' '+a.playState+' '+a.currentTime)` |
| 看元素真实布局尺寸 | `offsetWidth/offsetHeight`（**不受 transform 影响**） |
| 看 React 真实 props | `element[Object.keys(el).find(k=>k.startsWith('__reactFiber'))].return.memoizedProps` |
| 看 iframe 偏移 | `DOM.getDocument(pierce=True)` + `DOM.getBoxModel` 递归求 content quad 的 min |
| 调试弹窗是否打开 | 找 **可见且可点**的确认按钮，别用「容器宽度 > 0」 |

## 八、这次的收获（一句话版）

> **DOM 里读得到 ≠ 点得动；点得动 ≠ 业务生效。**
>
> 美团后台的每一个「元素不存在 / 按钮 disabled / 点了没反应」，
> 几乎都能在**动画时钟、事件委托、iframe 层级**这三层里找到解释。
> 而最高效的排查手段不是猜选择器，是**分层取证**：
> 先确认「元素在不在」→ 再确认「能不能点」→ 最后确认「点了业务变没变」。
